# Mark Scheme

## Code

| Criterion | Level 1 | Level 2 | Level 3 | Level 4 | Level 5 |
|---|---|---|---|---|---|
| **Code - Functionality** | The code does not run/it's fundamentally wrong or broken<br>***0 points*** | The code runs almost all or all that is essential, but some relevant portions are broken or missing.<br>***1 points*** | The code runs with flaws or warnings in non-essential aspects. These are not addressed or noted.<br>***2 points*** | The code is completely functional, with no errors or warnings that have not been addressed or understood.<br>***3 points*** | Not only is the code fully functional, but cross-compatibility or version issues are smartly addressed where relevant OR additional resources/references are provided for the user's benefit.<br>***4 points*** |
| **Code - Structure** | The code is written chaotically. Variables have strange or random, non-representative names. Code is laid out in a wrong order and does not follow good practices (indentation, coherence etc.)<br>***0 points*** | The code is written mostly chaotically. Some variables have business meaning, whereas most are arbitrary. Code follows close to no good practices and is badly ordered.<br>***1 points*** | The code is written in a standard, low-effort way. Variables are named intuitively, but it often misses conventions or good practice.<br>***2 points*** | The code follows a very clear structure, with meaningful variable names. It follows most good coding practices.<br>***3 points*** | The code structure is crystal clear, following all good coding practices. Additionally, the code is highly optimised, for example using OOP, self-made packages or modules.<br>***4 points*** |
| **Code - Comments** | The code has no comments<br>***0 points*** | The code has some very rudimentary comments, and on very specific portions/sections. Most lack comments at all.<br>***1 points*** | Some of the code was commented OR all the code was commented, but low effort/low quality. The same can be said about extra annotations.<br>***2 points*** | Comments are thoroughly used throughout the code, providing good insights.<br>***3 points*** | Comments and annotations are top quality, adding clarity and additional explanations to the code. They also provide references or resources where needed.<br>***4 points*** |
| **Code - Reproducible** | The code is inherently irreproducible. It fundamentally relies on aspects that are strictly local to the programmer.<br>***0 points*** | The code has very few reproducible sections. You can navigate a small percentage of it until you will need locally relevant files.<br>***1 points*** | Most of the code can be reproduced, albeit oftentimes difficult to do so<br>***2 points*** | All the code can easily be reproduced, i.e. runs from start to finish with no problems.<br>***3 points*** | The code is completely reproducible. Additionally, cross-compatibility or version aspects are addressed where necessary for running across different platforms, OSs etc.<br>***4 points*** |

## EDA

|---|---|---|---|---|---|
| **EDA - Quality Checks** | There were no quality checks whatsoever performed<br>***0 points*** | The bare minimal quality checks (equivalent to simply viewing the loaded data once) were carried out.<br>***1 points*** | Quality checks were carried out decently well (eg: tested for nulls, data types etc.) Some important ones were either left out, or carried out poorly.<br>***2 points*** | Quality checks were carried out accordingly, with good depth and understanding of their purpose.<br>***3 points*** | Quality checks were carried out to the highest standard, ensuring the data is understood and all aspects are tackled in detail. The team also went above and beyond, for instance explaining a possible meaning of the patterns and how they could be used or changed under various circumstances.<br>***3 points*** |
| **EDA - Process Logic** | Everything was done arbitrarily, with no clear intention in mind<br>***0 points*** | The process would make sense to the programmer, but almost no sense to anyone but them.<br>***1 points*** | The process followed some logical steps, but some decisions were taken without aiding explanations.<br>***2 points*** | The process was highly logical in its structure, easy to follow.<br>***3 points*** | The process was extremely logical and all steps were laid out in an easy to understand fashion. Ideally, it was all summarized OR loaded in a single, optimised query (function/class/module)<br>***4 points*** |
